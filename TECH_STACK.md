# Tech Stack — Doctor Diagnosis Assistant

Complete inventory of every technology used in the project, plus everything planned for future phases. Status & build history live in `PROGRESS.md`; architecture background in `project-roadmap.md` and `doctor-diagnosis-assistant-spec.md`.

---

## 1. Architecture at a glance

```
React SPA (Vite) ──▶ FastAPI backend ──┬──▶ scikit-learn classifier (local inference)
                                       └──▶ LLM provider chain (Groq → OpenRouter)
                    │
                    ▼
            PostgreSQL 17 (Docker)
```

Two prediction paths run on every case: a fast local classifier baseline and an LLM reasoning layer with fallback; both outputs are shown side by side to the doctor.

## 4. Machine learning (`ml/`) — in use

| Library | Version | Role |
|---|---|---|
| scikit-learn | >=1.5 | Classifier training + inference |
| pandas | >=2.0 | Data prep / feature handling |
| joblib | >=1.3 | Model serialization (`model.joblib`) |

**Champion model:** logistic regression (beat random forest on interpretability tie-break; CV + test macro-F1 = 1.00 — a dataset property, not a quality claim). Trained on the Kaggle Disease Prediction set: **131 symptoms → 41 diseases**, binary symptom vectors, stratified-CV selection, single final holdout eval. Cleaned artifacts are committed under `ml/artifacts/`, regenerable via `ml/data_prep.py`.

## 6. LLM reasoning layer — in use

No vendor SDK — raw `httpx` calls against OpenAI-compatible `/chat/completions` endpoints.

| Provider | Model (current) | Role |
|---|---|---|
| Groq (primary) | `openai/gpt-oss-120b` | First-choice reasoning model |
| OpenRouter (fallback) | `nvidia/nemotron-3-super-120b-a12b:free` | Auto-fallback on 429/error/malformed JSON |

**Mechanics:** strict-JSON prompt + lenient extraction; structured case assembler (demographics/HPI/symptoms/vitals/social/history/meds/allergies); classifier output fed in as cross-check hint; in-process content-keyed response cache (OrderedDict keyed by SHA256 of canonical payload) with `force_refresh` escape hatch; writer-role gated + audited. Free-tier only — Phase 1 synthetic data exclusively.

> Model IDs churn on free tiers — always verify against each provider's live `/models` catalog before trusting docs.

## 10. Planned — later phases / stretch goals

From the roadmap (not yet started):

- **Phase 2:** doctor-validation round with crafted fake cases (no new tech expected)
- **Phase 3 trigger work (real patient data):** consent flow, data-principal rights tooling, encryption at rest/in transit, breach-notification readiness, retention policy, India DPDP Act compliance review

- **Classifier scale-up:** diseases-symptoms-773 dataset (773 diseases / 377 symptoms); free-text symptom parsing via NLP/LLM step; **SHAP** explainability visualizations; confidence calibration testing
- **UX features:** body map UI for symptom location, voice input for dictation, multi-language support, patient trend views across visits
- **Clinical extras:** specialist-referral suggestions, drug-interaction checker
- **Ops:** offline/low-connectivity mode leaning on the local classifier, EHR/lab-equipment integration if hospital adoption happens

## 11. Explicitly rejected / avoided

| Choice | Reason |
|---|---|
| TypeScript on frontend | Student-project simplicity (plain JSX chosen) |
| axios | Thin native-fetch wrapper is enough |
| passlib / python-jose | Unmaintained — replaced by bcrypt + pyjwt |
| `openai` SDK for LLM calls | Raw httpx keeps deps lean; one failure path into the fallback chain |
| Postgres native ENUM types | Adding values would need `ALTER TYPE` migrations |
| Gemini as LLM provider | Free-tier quota exhaustion pain; superseded by Groq→OpenRouter chain |
